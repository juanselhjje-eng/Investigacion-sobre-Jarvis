# Criterios de evaluación: ventajas, desventajas y recomendación para menores

**Aplicación:** estos criterios se aplican a cada tecnología, modelo, interfaz, herramienta, proyecto y recomendación que se añada a esta investigación.

## Regla obligatoria por alternativa

Cada opción comparada debe incluir:
1. **Qué es y qué hace**, con alcance real y requisitos.
2. **Ventajas**, concretas y relevantes para el uso estudiado.
3. **Desventajas y riesgos**, incluidos los que aparecen en documentación, issues o pruebas.
4. **Coste total**, no solo precio anunciado: hardware, electricidad, API, suscripciones, almacenamiento, hosting y mantenimiento.
5. **Privacidad**, qué datos salen del dispositivo, quién los procesa, retención y opciones de borrado.
6. **Seguridad y control**, permisos, confirmaciones, cancelación, reversión y verificación.
7. **Facilidad para un principiante**, instalación, mantenimiento, documentación y posibilidad de recuperarse de errores.
8. **Balance para un menor de edad**, considerando edad mínima del servicio, privacidad, gastos, supervisión, comprensión del riesgo y control del usuario.
9. **Veredicto condicionado**, explicando para qué caso es la mejor opción y cuándo no lo es.
10. **Fuentes y nivel de evidencia**, con fecha y distinción entre documentación oficial, afirmación del creador, reporte comunitario, inferencia y prueba reproducida.

## Cómo decidir qué es mejor para un menor

No se elegirá automáticamente lo más potente, popular o barato. Se ponderarán:

- Privacidad y minimización de datos.
- Seguridad por defecto y permisos mínimos.
- Facilidad de apagar, cancelar, revisar y borrar.
- Coste cero o predecible; ninguna compra o API de pago sin autorización del adulto responsable.
- Compatibilidad con las condiciones de edad del proveedor; nunca recomendar eludir límites de edad.
- Utilidad educativa y posibilidad de comprender el funcionamiento.
- Fiabilidad demostrada, no solo promesas o vídeos editados.
- Uso de cuentas, archivos y credenciales de prueba antes de conectar información real.

## Formato mínimo de recomendación

Para cada comparación, cerrar con tres frases o apartados:

- **Mejor para empezar:** opción más sencilla y controlable para aprender.
- **Mejor cuando el proyecto crezca:** opción apropiada si hay requisitos demostrados y permisos adecuados.
- **No recomendar por ahora:** opciones que impliquen coste impredecible, permisos excesivos, datos sensibles o acciones irreversibles sin controles suficientes.

La etiqueta “para un menor” no significa que una herramienta sea automáticamente segura. Se deben revisar la edad mínima y los términos actuales de cada servicio, y consultar con un adulto responsable cuando haya cuentas, pagos, instalación de software, permisos del sistema o conexión a datos personales.

## Límites y honestidad

La recomendación es una evaluación práctica y no asesoría legal. Las reglas, precios y edades mínimas pueden cambiar. No afirmar que una herramienta fue probada si solo se revisó su documentación. No describir un modelo local como “privado” si el sistema también usa APIs remotas, telemetría o conectores externos.
